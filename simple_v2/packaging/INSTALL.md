# calls — расшифровка созвона на входе, связанная заметка на выходе

Распаковка этого архива делает агента созвонным. Всё едет здесь: скилл с
двумя скриптами, одна fleet-роль, правила доступа, два гайда и один
демонстрационный транскрипт. От образа не нужно ничего, кроме `python3`.

```
skills/calls/          скилл: контракт и два скрипта
  scripts/intake.py    присланный файл -> transcripts/<дата>-<id8>.md
  scripts/gate.py      вопросы владельцу, нарезка цитат, приёмка
roles/segment.md       единственная fleet-роль: карта тем, без цитат
cron/calls_ask.py      обёртка для крона: вопрос владельцу, без модели
vault/                 правила доступа, гайды, демо-транскрипт
```

## Установка

```bash
unzip -o calls.zip -d /opt/data/calls-pkg
cd /opt/data/calls-pkg && sh ./install.sh
```

`unzip` есть не в каждом образе агента. Тогда:

```bash
python3 -c "import zipfile; zipfile.ZipFile('calls.zip').extractall('/opt/data/calls-pkg')"
```

`sh ./install.sh`, а не `./install.sh`: архив несёт бит исполнения, но не
всякий распаковщик его восстанавливает, а `zipfile` в питоне отбрасывает права
вовсе. Через `sh` это неважно.

Это всё, и в первый раз, и при каждом обновлении. Скрипт печатает версию и
заканчивается тем же, чем проверяют работу руками: очередью созвонов.

Две половины ставятся по-разному:

- **Машинерия перезаписывается всегда.** У скилла, роли, правил доступа и
  гайдов одна правильная версия — та, что в архиве.
- **Библиотека засевается только если её нет.** После первой установки
  транскрипты и выросшие из них заметки принадлежат владельцу, и обновление,
  которое их перезапишет, сотрёт живое. Установщик считает и говорит:
  `library: 0 seeded, 3 left alone`.

Всё ложится под `/opt/data`, потому что только это переживает перезапуск.

## Четыре шага руками

Их не делает установщик, потому что каждый требует чужого решения.

**1. Включить fleet.** Роль `segment` работает на LLM-флоте (`fleet_id: codex`).
Пока флот выключен, карта тем не появится, а вопрос первых ворот всё равно
придёт. Проверить: роль видна в реестре флота, и её вебхук на изменения
существует.

**2. Завести крон вопроса.** Раз в пятнадцать минут, без модели, доставка
владельцу в Telegram:

```
скрипт:      /opt/data/scripts/calls_ask.py
расписание:  */15 * * * *
режим:       без агента (stdout уходит владельцу как есть)
```

Пустой stdout — тишина. Спрашивать чаще смысла нет: владелец отвечает не
секундами.

**3. Назвать владельца.** Переменная `CALLS_OWNER` в окружении агента — имя
владельца так, как он называет себя сам, например `Пётр Иванов`. По нему скилл
понимает, что владельца не надо заводить как нового человека. Не задана —
подставляется «Владелец», и первый же созвон заведёт карточку на самого
хозяина базы.

Имя должно совпадать с тем, которым владелец называет себя, отвечая на первые
ворота. Скилл сверяет имя из карты говорящих с этой переменной, и расхождение
в одну букву означает карточку «неподтверждённый человек» на владельца.

Необязательное: `CALLS_SINCE` — граница архива в виде `YYYY-MM-DD`. Созвоны
старше этой даты в базу попадут, но вопросов по ним владельцу не задают. По
умолчанию спрашивают про всё, что прислали.

**4. Синхронизировать волт.** Заметки остаются файлами, пока их не отправили в
базу; до этого для агента их не существует. Установщик пробует сделать это сам
и говорит, если не смог.

## Проверка

```bash
python3 /opt/data/skills/calls/scripts/gate.py status
```

Печатает очередь и ничего не пишет. Если установщик кончился строкой
`REFUSED: vault …`, машинерия на месте, а база не отвечает: разбирайтесь с
доступом к базе, ставить заново не нужно. Дальше проверка на демо-транскрипте:
скажите агенту «разбери созвон 4f01f193» — он должен задать вопрос о том, кто
говорил под метками `Speaker 1` и `Speaker 2`, а не ответить сам.

Приём файла проверяется на том же примере в сыром виде, `demo/call.txt`:

```bash
python3 /opt/data/skills/calls/scripts/intake.py \
  --file /opt/data/calls-pkg/demo/call.txt --date 2026-01-15 --dry-run
```

`--dry-run` печатает заметку и ничего не пишет. Без него скрипт откажется:
этот транскрипт уже засеян установщиком, и повтор ловится по отпечатку текста.

## Обновление

```bash
sh ./install.sh
```

Скилл читается агентом при старте сессии, поэтому после обновления скилла
владельцу нужна новая сессия с ботом (`/new`). Без этого агент работает по
старому контракту и не видит новых команд.
